# 基金守望个人部署步骤（小白版）

本文对应基金守望 `0.1.0`，验证环境为 Windows、Node.js `24.19.0`、npm `11.17.0`、Next.js `16.1.6`。GitHub、Supabase、Server酱都是网页服务，网页菜单名称以后可能略有变化。

## 开始前先知道

完成后，平时使用不需要打开GitHub：

- 安卓手机：点击桌面的“基金守望”图标。
- 电脑：打开收藏的网址，或安装成浏览器应用。
- GitHub只负责后台发布和定时分析。
- 支付宝仍然是唯一执行买入、卖出和确认金额的地方。

需要准备一个GitHub账号、一个常用邮箱、一个微信号。所有密钥都由你本人复制到平台的加密输入框，不要发送到聊天、截图或代码文件中。

## 第一阶段：创建Supabase同步空间

1. 打开 [Supabase官网](https://supabase.com/)，登录后点击 `New project`。
2. `Name` 可填 `fund-watch`。
3. 设置数据库密码并自己保存。这个密码不需要发给任何人。
4. 选择离你较近的区域，点击创建，等待项目完成初始化。
5. 左侧点击 `SQL Editor`，点击 `New query`。
6. 在电脑打开本项目的 `doc/supabase.sql`，全选并复制全部内容。
7. 粘贴到Supabase SQL编辑框，点击 `Run`。
8. 看到成功提示后，左侧进入 `Project Settings` → `API`：
   - 复制 `Project URL`。
   - 复制 `anon public`（或新版界面中的 publishable/anon key）。
   - 找到 `service_role` key，但此时只确认它存在，不要放进代码。

如果你以前已经运行过旧版建表脚本，不要重复运行整份 `doc/supabase.sql`。请在 `SQL Editor` 新建查询，只复制并运行 `doc/supabase-公开信息分析升级.sql`，它会为网页里的“今日公开信息”补充保存字段。

### 只允许你自己注册

初次登录前，Supabase的邮箱注册要暂时开启。等你成功登录基金守望一次后：

1. 回到Supabase → `Authentication` → `Users`，确认列表中已有你的邮箱。
2. 进入 `Authentication` → `Sign In / Providers` → `Email`。
3. 关闭允许新用户注册（界面通常显示 `Allow new users to sign up`）。
4. 保存。以后你的已有邮箱仍可用验证码登录，陌生邮箱不能新建账号。

## 第二阶段：创建自己的GitHub仓库

1. 打开 [GitHub新建仓库页](https://github.com/new)。
2. `Repository name` 建议填 `fund-watch`。
3. 为了免费和部署简单，选择 `Public`。公开的是程序源代码，不是你的Supabase持仓数据。
4. 不要勾选自动创建README、`.gitignore`或License，因为本地项目已经有这些文件。
5. 点击 `Create repository`。

项目代码第一次推送可以由Codex继续完成；需要登录GitHub或确认授权时由你本人操作。

## 第三阶段：加入页面发布所需的两个加密变量

在你自己的GitHub仓库页面中：

1. 点击 `Settings`。
2. 左侧点击 `Secrets and variables` → `Actions`。
3. 点击 `New repository secret`，依次创建：
   - `NEXT_PUBLIC_SUPABASE_URL`：值填Supabase `Project URL`。
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`：值填Supabase `anon public` key。
4. 左侧点击 `Pages`。
5. `Build and deployment` → `Source` 选择 `GitHub Actions`。
6. 回到仓库顶部 `Actions`，打开 `Deploy fund watch to GitHub Pages`，点击 `Run workflow`。
7. 任务出现绿色对勾后，在 `Settings` → `Pages` 复制网站地址，通常类似：
   `https://你的GitHub用户名.github.io/fund-watch/`

## 第四阶段：第一次登录和同步

1. 用电脑打开刚才的网站地址。
2. 点击右上角用户图标 → `登录`。
3. 输入你的邮箱，点击发送验证码。
4. 去邮箱查看验证码，回到基金守望完成验证。
5. 选择保守、稳健、进取或自定义风险模式，并设置投资总额、保留现金和仓位上限。
6. 使用搜索添加基金，或点击截图按钮导入支付宝基金截图。
7. 核对基金代码、份额和成本后再确认导入。
8. 点击右上角用户图标 → `同步`，等待显示同步完成。
9. 回Supabase关闭新用户注册，方法见第一阶段。

## 第五阶段：连接微信提醒

1. 打开 [Server酱 Turbo](https://sct.ftqq.com/)，按页面提示登录并绑定微信推送。
2. 在Server酱后台找到并复制 `SendKey`。不要截图或发给别人。
3. Supabase打开 `Authentication` → `Users`，复制你这一行的 `User UID`。
4. Supabase打开 `Project Settings` → `API`，显示并复制 `service_role` key。
5. 回GitHub仓库 → `Settings` → `Secrets and variables` → `Actions`。
6. 新建下面四个 `Repository secrets`：
   - `SUPABASE_URL`：Supabase Project URL。
   - `SUPABASE_SERVICE_ROLE_KEY`：Supabase service_role key。
   - `FUND_WATCH_USER_ID`：你的Supabase User UID。
   - `SERVERCHAN_SENDKEY`：Server酱 SendKey。

其中 `SUPABASE_SERVICE_ROLE_KEY` 权限最高。它只能放在GitHub的Secret输入框，不能写入 `.env`、README、聊天或任何截图。

### 手动测试一次

1. GitHub仓库顶部点击 `Actions`。
2. 左侧点击 `Daily fund analysis`。
3. 点击 `Run workflow`。
4. 第一次选择 `evening`，再点击绿色运行按钮。
5. 等任务变成绿色对勾，微信应收到“基金守望：晚间持仓日报”；报告中会包含当天持仓基金公告、相关新闻、筛选原因和参考动作。
6. 如果任务失败，点击失败步骤，只查看最后一行错误即可；日志不会输出持仓明细。

## 自动分析时间

- 交易截止前提醒：工作日中午12:00到14:55每10分钟左右检查一次，但只会在你设置的提前分钟数到达后推送一次。
- 晚间日报：每天18:10到23:10每小时检查，按页面设置的小时推送一次；周末也会检查新公告和新闻。
- GitHub定时任务可能有数分钟延迟，不适合用作秒级交易工具。
- 非交易日如果没有当日估值，交易窗口提醒会自动跳过。
- `fund_watch_reports` 表保存“某日某类报告是否已发送”和不含持仓金额的公开信息摘要，用于网页展示并防止重复微信提醒。

## 安装到安卓手机桌面

以下以安卓Chrome当前常见菜单为例：

1. 在Chrome打开基金守望网站。
2. 点右上角三个点。
3. 点击 `添加到主屏幕` 或 `安装应用`。
4. 名称保持“基金守望”，点击 `安装`。
5. 回到手机桌面，会看到基金守望图标。以后从图标打开即可，不需要打开GitHub。

在手机用同一邮箱验证码登录后，点 `同步` 即可读取电脑端数据。

## 安装到电脑

以Microsoft Edge为例：

1. 用Edge打开基金守望网站。
2. 点右上角三个点 → `应用` → `将基金守望安装为应用`。
3. 点击 `安装`，可选择固定到任务栏或桌面。

## 出现问题时先检查

- 页面404或没有样式：确认GitHub Pages的Source是 `GitHub Actions`，并重新运行发布任务。
- 登录提示“未配置Supabase”：检查两个 `NEXT_PUBLIC_` Secret名称是否完全一致，然后重新运行页面发布。
- 手机电脑数据不同：两端必须用同一邮箱登录，并各点一次 `同步`。
- 定时任务提示找不到同步数据：先在页面登录、录入一只基金并手动同步。
- 提示缺少 `fund_watch_reports`：新项目运行最新版 `doc/supabase.sql`；旧项目运行 `doc/supabase-公开信息分析升级.sql`。
- 微信没收到：确认Server酱已绑定微信、SendKey未多空格，再手动运行一次晚报。
- 定时任务长期不运行：GitHub可能暂停长期无代码活动仓库的定时任务，可在Actions页面重新启用并手动运行一次。
